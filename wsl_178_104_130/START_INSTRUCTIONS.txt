ИНСТРУКЦИЯ ПО ЗАПУСКУ WSL VPN
WSL → 178 → 104 → 130 и WSL → 104 → 130
Дата: 2026-08-28

============================================================
1. ГЛАВНОЕ
============================================================

Есть два сохранённых профиля:

  104-130       WSL → 203.0.113.10 → 198.51.100.130
  178-104-130   WSL → 203.0.113.20 → 203.0.113.10 → 198.51.100.130

Ожидаемый внешний IP для обоих профилей:

  198.51.100.130

Одновременно должен работать только один профиль и один TUN.
Выбранный профиль автоматически восстанавливается при полном старте WSL.
Старый профиль 104-130 не удалён и используется для быстрого rollback.

============================================================
2. ОБЫЧНЫЙ ЗАПУСК ЧЕРЕЗ 178
============================================================

Из WSL:

  sudo /usr/local/bin/vless-wsl use 178-104-130

Из Windows PowerShell:

  wsl.exe -d Ubuntu-24.04 -u root -- /usr/local/bin/vless-wsl use 178-104-130

Команда сама:

  - проверит конфиги;
  - выполнит preflight через 178;
  - применит killswitch;
  - остановит старый TUN;
  - поднимет tun-vless178130;
  - дождётся exit IP 198.51.100.130;
  - при ошибке выполнит rollback на 104-130.

Не закрывать окно до появления строки:

  HEALTHY profile=178-104-130 exit=198.51.100.130 fail_closed=yes

============================================================
3. ВОЗВРАТ НА СТАРУЮ СХЕМУ 104 → 130
============================================================

Из WSL:

  sudo /usr/local/bin/vless-wsl use 104-130

Из Windows PowerShell:

  wsl.exe -d Ubuntu-24.04 -u root -- /usr/local/bin/vless-wsl use 104-130

Успешный результат:

  HEALTHY profile=104-130 exit=198.51.100.130 fail_closed=yes

Файлы профиля 178 при этом не удаляются. Останавливаются только его процессы.

============================================================
4. ПРОВЕРКА СОСТОЯНИЯ
============================================================

Из WSL:

  sudo /usr/local/bin/vless-wsl status
  sudo /usr/local/bin/vless-wsl check

Из Windows PowerShell:

  wsl.exe -d Ubuntu-24.04 -u root -- /usr/local/bin/vless-wsl status
  wsl.exe -d Ubuntu-24.04 -u root -- /usr/local/bin/vless-wsl check

Для активного профиля 178 нормальный status:

  selected=178-104-130
  old_profile=stopped
  new_profile=running
  tun=tun-vless178130
  allowed_transport=203.0.113.20:443
  exit=198.51.100.130

Для активного профиля 104 нормальный status:

  selected=104-130
  old_profile=running
  new_profile=stopped
  tun=tun-vless130
  allowed_transport=203.0.113.10:443
  exit=198.51.100.130

------------------------------------------------------------
4.1. SSH, SCP И SSH-ТУННЕЛИ К AEZA ЧЕРЕЗ WSL
------------------------------------------------------------

Обычный вход:

  ssh root@203.0.113.20

Пример локального port-forward:

  ssh -L 127.0.0.1:18080:127.0.0.1:8080 root@203.0.113.20

Пример SOCKS-туннеля:

  ssh -D 127.0.0.1:1081 root@203.0.113.20

SSH, SCP, SFTP, -L, -R и -D идут через активный VPN/TUN. Только служебное
соединение Xray к 203.0.113.20:443 направляется напрямую через eth0.

Не указывать BindAddress интерфейса eth0 и не использовать ssh -b с адресом
eth0: прямой обход VPN намеренно блокируется killswitch.

Проверить маршрут SSH можно командой:

  ip route get 203.0.113.20 ipproto tcp dport 22

В результате должен быть указан dev tun-vless178130 и table 2022.

Проверено 2026-08-28: вход на Aeza из WSL успешен. На стороне Aeza переменная
SSH_CONNECTION показывает source 198.51.100.130 — реальный IP Windows/WSL не
передаётся. Если появляется "Connection reset by peer", сначала выполнить
`vless-wsl check`; не добавлять прямой allow для eth0:22.

============================================================
5. АВТОЗАПУСК ПОСЛЕ ПЕРЕЗАПУСКА WSL
============================================================

Выбранный профиль хранится здесь:

  /etc/vless-wsl/profile

Для полного перезапуска WSL выполнить в Windows PowerShell:

  wsl.exe --shutdown

Следующий запуск Ubuntu автоматически:

  1) немедленно закроет прямой IPv4/IPv6 OUTPUT;
  2) применит полный killswitch выбранного профиля;
  3) запустит и проверит VPN;
  4) только после этого запустит фоновые сервисы.

После запуска проверить:

  wsl.exe -d Ubuntu-24.04 -u root -- /usr/local/bin/vless-wsl check

Внимание: wsl.exe --shutdown завершает все открытые WSL-процессы и терминалы.

============================================================
6. ПРОВЕРКА KILLSWITCH
============================================================

Без изменения рабочего firewall, в отдельном network namespace:

  sudo /usr/local/bin/vless-wsl test-rules

Ожидаемый итог:

  ALL_KILLSWITCH_RULESETS_OK

Живой fail-closed тест активного профиля:

  sudo /usr/local/bin/vless-wsl test-fail-closed

Этот тест временно останавливает активный TUN, проверяет блокировку трафика и
автоматически восстанавливает тот же профиль. Нормальный результат:

  FAIL_CLOSED_OK profile=<профиль> default=blocked eth0=blocked ipv6=blocked
  HEALTHY profile=<профиль> exit=198.51.100.130 fail_closed=yes

============================================================
7. ЕСЛИ ПРОФИЛЬ НЕ ПОДНЯЛСЯ
============================================================

Сначала посмотреть состояние:

  sudo /usr/local/bin/vless-wsl status
  sudo /usr/local/bin/vless-wsl check
  sudo cat /run/vless178130-switch.state 2>/dev/null
  sudo tail -100 /tmp/vless178130-switch.log 2>/dev/null
  sudo tail -100 /tmp/xray-vless178130.log 2>/dev/null
  sudo tail -100 /tmp/sing-vless178130.log 2>/dev/null

Самый безопасный аварийный возврат:

  sudo /usr/local/bin/vless-wsl use 104-130

После возврата обязательно проверить:

  sudo /usr/local/bin/vless-wsl check

Если нужен повторный запуск 178:

  sudo /usr/local/bin/vless-wsl use 178-104-130

============================================================
8. ЧЕГО НЕ ДЕЛАТЬ
============================================================

  - Не запускать вручную оба sing-box TUN одновременно.
  - Не выполнять iptables -F: это удалит killswitch.
  - Не запускать файлы *.example.sh вместо штатной команды vless-wsl.
  - Не копировать UUID Windows-профиля: он использует другой серверный маршрут.
  - Не удалять каталог wsl_130: это рабочий rollback-профиль.

# Временный файлообменник на 104 (скрытая ссылка с авто-сгоранием)

Дата актуализации: 2026-06-01. Как раздать клиенту файл по прямой ссылке через маскировочный сайт `vpn.example.com`, не светя его на сайте и с авто-удалением через N часов.

> TL;DR: файл кладётся в `/var/www/html/<случайный-токен>/<имя>` на 104 → доступен по `https://vpn.example.com/<токен>/<имя>`. Каталог не листится (`403`), нигде не залинкован — открыть можно только по точной ссылке. Через 48 ч `dl-reaper` (cron) удаляет каталог → ссылка отдаёт `404`.

---

## 1. Почему это вообще работает

На 104 стоит **обычный nginx**, отдаёт docroot `/var/www/html` (это и есть «блог» `vpn.example.com`). Reality на `:443` для не-VPN клиентов (обычный браузер/curl) прозрачно форвардит TLS на `dest 127.0.0.1:8443` — это тот же nginx с LE-сертификатом на `vpn.example.com`. Поэтому **любой файл из `/var/www/html` качается снаружи** по `https://vpn.example.com/...` как с обычного HTTPS-сайта. То же отдаётся и по `:80`.

Server-блоки nginx (104):
- `listen 127.0.0.1:8443 ssl http2; server_name vpn.example.com; root /var/www/html;` ← сюда форвардит Reality
- `listen 80 default_server; root /var/www/html;`
- `location / { try_files $uri $uri/ =404; }`, **`autoindex` выключен** → заход в каталог без индекс-файла даёт `403/404`, листинга нет.

«Не видно на сайте» = каталог не залинкован с блога + не листится + имя токена неугадываемое. Защита — это **обскурность пути** (для временной раздачи на 48 ч достаточно). По сути это публичный HTTPS: кто получит точный URL — скачает. Для жёсткой защиты — basic-auth или `secure_link` (см. §6).

## 2. Грабли заливки больших файлов на 104

Прямая заливка на 104 идёт через SSH-джамп (`WSL → Aeza → 104`, см. `OPERATIONS.md`). Для **крупных** файлов он нестабилен — рвётся через ~300 КБ–3 МБ (`Broken pipe`), `scp`/`cat` так не дотащить. Рабочие обходы:

- **Крупный ПУБЛИЧНЫЙ файл (напр. v2rayN с GitHub):** пусть его качает **сам 104** напрямую по HTTPS — killswitch разрешает исходящий `443/tcp`. Лондонский VPS тянет с GitHub-CDN на скорости диска. Версию подтверждаем **байт-в-байт по sha256** (см. §3).
- **Мелочь (конфиги, картинки, до ~десятков МБ):** `rsync --append-verify` в цикле-докачке через джамп (переживает обрывы):
  ```bash
  rsync -rt --partial --append-verify --timeout=90 -e <ssh-через-джамп> ./pkg/ root@104:/root/pkg/
  ```
- **Сборку архива делаем на 104** (`zip` там не установлен — используем `python3 -m zipfile` / `zipfile` API; `ZIP_STORED`, т.к. содержимое уже сжато).
- Быстрый прямой канал к 104 — это `104:443` по eth0 (сам вход VPN, разрешён WSL-killswitch'ем). Именно по нему мы и **скачиваем** готовый архив обратно (а не через джамп).

## 3. Как собрали текущую раздачу (пример, 2026-06-01)

Задача: отдать клиенту один zip = приложение v2rayN (Windows) + конфиги + видео/фото.

1. Локально (WSL) собрали список и посчитали `sha256`/размер `v2rayN-windows-64.zip` (`142864141` байт, sha `7a04697c…62f7e`).
2. На 104 нашли релиз с **точно таким же размером** ассета через GitHub API:
   ```bash
   curl -fsSL 'https://api.github.com/repos/2dust/v2rayN/releases?per_page=100' \
    | jq -r --argjson sz 142864141 '.[]|.tag_name as $t|.assets[]?|select(.name=="v2rayN-windows-64.zip" and .size==$sz)|"\($t) \(.browser_download_url)"'
   # -> 7.18.0
   ```
3. 104 скачал этот ассет напрямую (`curl` по 443, в фоне через `setsid`, чтобы пережить обрыв управляющего канала) и **sha256 совпал** с локальным → байт-в-байт та же версия.
4. Мелочь (~16 МБ: 2 mp4 + jpg + 3 конфига) залили в `/root/pkg` через `rsync --append-verify`.
5. Собрали zip на 104 (`python3`, `ZIP_STORED`) в `/var/www/html/<токен>/<имя>.zip`, проверили `testzip()` и `Content-Length` по nginx.
6. Имя каталога и файла — **только цифры** (удобно диктовать): `…/275021360440/5299943564.zip`.

**Активная ссылка (сгорит 2026-06-03 ~21:07 UTC):**
```
https://vpn.example.com/275021360440/5299943564.zip
```
Содержимое: `v2rayN-windows-64.zip` (7.18.0), `client17/18/19.txt`, `2026-06-01_19-14-33.mp4`, `document_5253691021094591553.mp4`, `photo_5253691021554557536_y.jpg`. ⚠️ Внутри — конфиги-доступы; ссылка скрытая и сгорает, но точный URL = скачивание.

## 4. Авто-удаление через 48 ч (reboot-safe)

Механизм не зависит от `at`/systemd-таймеров (которые не переживают ребут) — обычный cron + реестр сроков:

- реестр: `/root/.dl-expiry/<токен>` содержит epoch-время сгорания;
- `/usr/local/sbin/dl-reaper.sh`:
  ```bash
  #!/bin/bash
  now=$(date +%s)
  for f in /root/.dl-expiry/*; do
    [ -e "$f" ] || continue
    tok=$(basename "$f"); exp=$(cat "$f" 2>/dev/null || echo 0)
    if [ "$now" -ge "$exp" ]; then rm -rf "/var/www/html/$tok" "$f"; logger "dl-reaper removed $tok"; fi
  done
  ```
- cron: `*/15 * * * * /usr/local/sbin/dl-reaper.sh` (проверка каждые 15 мин; cron поднимается после ребута → срок соблюдается).

Переименование раздачи = `mv` каталога **и** записи в `/root/.dl-expiry/` (дата сгорания сохраняется).

## 5. Рецепт: захостить новый файл

```bash
# на 104 (через джамп):
TOKEN=$(tr -dc 0-9 </dev/urandom | head -c 12)        # путь только из цифр
mkdir -p /var/www/html/$TOKEN
# ...положить файл(ы): rsync-докачкой, либо 104 сам curl'ит публичный источник по 443...
chmod 755 /var/www/html/$TOKEN; chmod 644 /var/www/html/$TOKEN/*
echo $(( $(date +%s) + 48*3600 )) > /root/.dl-expiry/$TOKEN   # срок 48 ч
# убедиться, что есть /usr/local/sbin/dl-reaper.sh и cron */15 (см. §4)

# проверка отдачи (локально, тот же server-block, что у Reality):
curl -skI -H 'Host: vpn.example.com' "https://127.0.0.1:8443/$TOKEN/<имя>" | grep -iE 'HTTP/|content-length'
curl -sk -o /dev/null -w '%{http_code}\n' -H 'Host: vpn.example.com' "https://127.0.0.1:8443/$TOKEN/"   # ждём 403 (листинга нет)
```
Ссылка клиенту: `https://vpn.example.com/$TOKEN/<имя>`.

Скачать/проверить «как клиент» (с любой точки, форсируя IP 104, мимо DNS):
```bash
curl -fL --resolve vpn.example.com:443:203.0.113.10 -o out.zip https://vpn.example.com/$TOKEN/<имя>
```

## 6. Если нужна защита жёстче обскурности

- **Пароль на zip** при сборке (`zipfile` с шифрованием умеет слабо; лучше `7z a -p`).
- **basic-auth** на каталог: отдельный `location /<токен>/ { auth_basic ...; }` в nginx (правка конфига + reload).
- **`secure_link`** — подписанные URL с истечением по времени на уровне nginx (нужен модуль `ngx_http_secure_link_module`).

Для разовой раздачи на 48 ч обычно достаточно цифрового токена + авто-сгорания.
